Part 01 · Conversion

Three types, three bridges

Simple meaning: Oracle keeps text, numbers and dates in different boxes. A conversion function is a bridge that moves a value from one box to another.

Why we need bridges

        
A user types '09-10-2026' in a form. That is just text. To add 30 days, Oracle must first read it as a DATE. To show salary as $1,250.50 on a report, the NUMBER must become text with a format.

      

      

        
The format model

        
Most bridges take a second argument, the format model (also called a mask). It tells Oracle how the text looks: 'DD-MM-YYYY', '$9,999.99'.

        
TO_CHAR(value, 'format')
TO_NUMBER(text, 'format')
TO_DATE(text, 'format')

      

      

        
6Quick check

        
Which bridge turns '15-AUG-2026' into a value you can subtract from another date?

        
        
TO_DATE
Text → DATE. Only then does date arithmetic work.

      

    

  







  

    
Conversion · Implicit vs Explicit

    
Implicit vs explicit conversion

    
Implicit: Oracle quietly converts for you when the types don't match. Explicit: you convert on purpose with TO_CHAR, TO_NUMBER or TO_DATE. Oracle recommends explicit: it is clearer and does not depend on session settings.

4Explicit is safer

        
-- implicit: depends on NLS_DATE_FORMAT
WHERE hire_date = '09-OCT-26'

-- explicit: always works
WHERE hire_date = TO_DATE('09-10-2026', 'DD-MM-YYYY')

      

      

        
Formal definition

        
        
Implicit conversion
Oracle automatically converts a value to the data type expected by the operation, when a sensible conversion exists. It fails at run time if the value cannot be converted (for example ORA-01722).
Explicit conversion
You specify the conversion with a SQL function. Oracle recommends explicit conversion because implicit conversion can be slower, can stop an index being used, and depends on NLS session parameters.

'25' is implicitly converted to the NUMBER 25 because * needs numbers.

      

    

  







  

    
Conversion · TO_CHAR(date)

    
TO_CHAR with dates

    
Simple meaning: a date is stored as numbers. TO_CHAR paints it as text, and the format model is the stencil. Each element in the stencil is replaced by one part of the date.

Watch out · padding

        
MONTH and DAY are padded with blanks to the length of the longest name (SEPTEMBER and WEDNESDAY, 9 letters). So 'Month' for October gives 'October  '. Add fm (fill mode) to remove the blanks and leading zeros.

      

    

    

      

        
3SQL syntax

        
TO_CHAR(date, 'format_model')

        
The format model goes in single quotes. Text you want printed as-is goes in double quotes: 'DD "of" Month'. Letter case matters: MONTH → OCTOBER, Month → October, month → october.

      

      

        
4Example

        
SELECT last_name,
       TO_CHAR(hire_date, 'fmDD Month YYYY') AS hired
FROM   employees;

        
LAST_NAMEHIRED
King17 June 2003

      

      

        
6Quick check · predict

        
SELECT TO_CHAR(DATE '2026-03-05', 'fmMonth DDth') FROM DUAL;

        
        
March 5th
fm removes the padding after March and the leading zero of 05. th adds the ordinal suffix.

      YY vs RR · which century?
      
        
      Two-digit years are ambiguous. Type a 2-digit year and compare.
      
        
      
        
      
          
      YY
      
          
      RR
      
        
      
        
      
        
      00–49 → 20xx50–99 → 19xx
      
      
      
    
      
    
      
      
      
        
      3SQL syntax
      
        
      TO_DATE(text, 'format_model')
      
        
      Oracle is forgiving by default: / can match -, extra spaces are fine. Put FX at the start of the format to demand an exact match.
      
      
      
      
      
        
      4Example
      
        
      SELECT last_name, hire_date
FROM   employees
WHERE  hire_date > TO_DATE('01-01-2018', 'DD-MM-YYYY');
      
      
      
      
      
        
      Formal definition
      
        
        
      RR
      If the current year's last two digits are 0–49: a 2-digit year 0–49 is in the current century, 50–99 in the previous century. If the current year's last two digits are 50–99: 0–49 is in the next century, 50–99 in the current century.
      YY
      Always the current century.
      Missing parts
      A missing year defaults to the current year, a missing month to the current month, a missing day to 1, and a missing time to 00:00:00.

      Conversion · TO_TIMESTAMP
      
    
      TO_TIMESTAMP
      
    
      Simple meaning: like TO_DATE, but the result is a TIMESTAMP, which can keep fractions of a second (up to 9 digits). Use the FF element to read the fraction.
      
  
      
  
      
    
      
      
      
        
      2Visual explanation · try it yourself

      AS DATE · TO_DATE
      no fraction: stops at seconds
      
          
      AS TIMESTAMP · TO_TIMESTAMP
      keeps the fraction

      3SQL syntax
      
        
      TO_TIMESTAMP(text, 'format_model')
      
        
      FF reads any number of fraction digits (up to 9). FF3 reads at most 3. The result is shown with NLS_TIMESTAMP_FORMAT, by default 'DD-MON-RR HH.MI.SSXFF AM' (X is the decimal point).

      Conversion · Nesting
      
    
      Nesting functions
      
    
      Simple meaning: a function can sit inside another function. Oracle works from the inside out: the innermost function runs first, and its answer becomes the input of the next one.
      
  
      
  
      
    
      2Pick an expression · step from the inside out
      
    
      
    
      
    
      
      
      
      
    
      
    
      
  
      
  
      
    
      
      
      3How to read a nested call
      
      
      F3( F2( F1(col, arg1), arg2 ), arg3 )
--          └─ 1st ─┘
--      └──────── 2nd ────────┘
-- └──────────────── 3rd ────────────────┘
      
      
      Single-row functions can be nested to any depth. Read the innermost brackets first, write down the result, then move outward.

      Part 02 · Conditional Expressions · NVL
      
    
      NVL
      
    
      Simple meaning: NULL means "unknown", and any arithmetic with NULL gives NULL. NVL is a stand-in: if the first value is NULL, use the second value instead.
      
  
      
  
      
    
      
      
      
        
      2See NULL spoil a calculation · then fix it
      
        
      
          
        
      
        
      
        
      Annual pay = salary*12 + salary*12*commission_pct. Click a row to trace it.
      
        
      
      
      
      
      
        
      5The SQL
      
        
      
      
      
    
      
    
      
      
      
        
      3SQL syntax
      
        
      NVL(expr1, expr2)
      
        
      If expr1 is NULL → return expr2. Otherwise → return expr1. Both must be the same data type (or convertible to expr1's type).
      
      
      
      
      
        
      Data type trap · test it
      
        
      
        
      
      
      
      
      
        
      6Quick check · predict
      
        
      SELECT NVL(NULL, 'N/A') FROM DUAL;
      
        
        
      N/A
      The first value is NULL, so NVL returns the second.
      
      
      
    
      
  
      

      



      
  
      
    
      Conditional Expressions · NVL2
      
    
      NVL2
      
    
      Simple meaning: NVL2 asks one question: "Is there a value?" If yes, return the 2nd argument. If no (NULL), return the 3rd. Notice the first value itself is never returned.
      
  
      
  
      
    
      
      
      
        
      2Visual explanation · flip the value
      
        
      
          
      
          
        
      
        
      
        
      
      
      
      
      
        
      5The SQL
      
        
      
      
      
    
      
    
      
      
      
        
      3SQL syntax
      
        
      NVL2(expr1, expr2, expr3)
      
        
      expr1 NOT NULL → expr2. expr1 NULL → expr3. expr2 and expr3 should be the same type.
      
      
      
      
      
        
      4Example
      
        
      SELECT last_name,
       NVL2(commission_pct, 'SAL+COMM', 'SAL') AS income
FROM   employees;
      
      
      
      
      
        
      6Quick check · predict
      
        
      SELECT NVL2(0, 'Yes', 'No') FROM DUAL;
      
        
        
      Yes
      0 is a real value, not NULL. NVL2 only checks for NULL.
      
      
      
    
      
  
      

      



      
  
      
    
      Conditional Expressions · NULLIF
      
    
      NULLIF
      
    
      Simple meaning: NULLIF compares two values. If they are equal, it returns NULL. If they are different, it returns the first one. It is the opposite job of NVL: it creates a NULL.
      
  
      
  
      
    
      
      
      
        
      2Visual explanation · try it yourself
      
        
      
          
      
          
      
        
      
        
      Try:
          
          
        
      
        
      
      
      
      
      
        
      Real use · avoid divide-by-zero
      
        
      
          
      
          
      
        
      
        
      
      
      
    
      
    
      
      
      
        
      3SQL syntax
      
        
      NULLIF(expr1, expr2)
      
        
      Same as CASE WHEN expr1 = expr2 THEN NULL ELSE expr1 END. expr1 cannot be the literal NULL.
      
      
      
      
      
        
      4Example
      
        
      SELECT first_name, last_name,
       NULLIF(LENGTH(first_name),
              LENGTH(last_name)) AS result
FROM   employees;
      
        
      FIRST_NAMELAST_NAMERESULT
      EllenAbel5
      CurtisDavies(null)

      SELECT NULLIF('A', 'B') FROM DUAL;
      
        
        
      A
      They are different, so the first value is returned.
      
      
      
    
      
  
      

      



      
  
      
    
      Conditional Expressions · COALESCE
      
    
      COALESCE
      
    
      Simple meaning: COALESCE walks a list from left to right and returns the first value that is not NULL. It stops as soon as it finds one, and never looks at the rest.
      
  
      
  
      
    
      
      
      
        
      2Click a box to make it NULL · then scan
      
        
      
        
      
        
      
      
      
      
      
        
      5The SQL
      
        
      
      
      
    
      
    
      
      
      
        
      3SQL syntax
      
        
      COALESCE(expr1, expr2, ..., exprN)
      
        
      Takes two or more values, all of the same data type family. COALESCE(a, b) works like NVL(a, b), but COALESCE can take a whole list and stops evaluating at the first non-NULL value.
      
      
      
      
      
        
      4Example
      
        
      SELECT last_name,
       COALESCE(manager_id, commission_pct, -1) AS m
FROM   employees;
      
        
      King has no manager and no commission, so he gets -1.
      
      
      
      
      
        
      6Quick check · predict
      
        
      SELECT COALESCE(NULL, NULL, 7, 9) FROM DUAL;
      
        
        
      7
      The first non-NULL value from the left. 9 is never looked at.

      Conditional Expressions · CASE
      
    
      CASE expression
      
    
      Simple meaning: CASE is IF-THEN-ELSE inside SQL. Oracle checks each WHEN from top to bottom, returns the THEN of the first match, and ignores the rest. No match and no ELSE? The result is NULL.
      
  
      
  
      
    
      
      
      
        
      2Pick an employee · watch the ladder
      
        
      
          
      
          
      
          
          
        
      
        
      
        
      
        
      
      
      
      
      
        
      5Result for every row
      
        
      
      
      
    
      
    
      
      
      
        
      3SQL syntax · two forms
      
        
      -- simple: compare one expression for equality
CASE expr WHEN v1 THEN r1
          WHEN v2 THEN r2
          ELSE rN
END

-- searched: any condition
CASE WHEN cond1 THEN r1
     WHEN cond2 THEN r2
     ELSE rN
END
      
        
      All the THEN/ELSE results must be the same data type. CASE is ANSI standard SQL.
      
      
      
      
      
        
      6Quick check · predict
      
        
      SELECT CASE 5 WHEN 1 THEN 'one' WHEN 2 THEN 'two' END FROM DUAL;
      
        
        
      NULL
      No WHEN matches and there is no ELSE, so the result is NULL.
      
      
      
    
      
  
      

      



      
  
      
    
      Conditional Expressions · DECODE
      
    
      DECODE
      
    
      Simple meaning: DECODE is Oracle's older, compact version of a simple CASE. It reads its arguments in pairs: "if it equals this, return that". A last unpaired argument is the default.
      
  
      
  
      
    
      
      
      
        
      2Pick an employee · read the pairs
      
        
      
          
      
          
          
        
      
        
      
        
      
        
      
      
      
      
      
        
      DECODE vs CASE with NULL
      
        
      Find employees with no commission:
      
        
      
        
      Key difference: DECODE treats two NULLs as a match. In CASE, WHEN NULL never matches, because NULL = NULL is not true. Use CASE WHEN commission_pct IS NULL instead.
      
      
      
    
      
    
      
      
      
        
      3SQL syntax
      
        
      DECODE(expr,
       search1, result1,
       search2, result2,
       default)
      
        
      No match and no default → NULL. DECODE is Oracle-only; CASE works in every database.
      
      
      
      
      
        
      6Quick check · predict
      
        
      SELECT DECODE('B', 'A', 1, 'B', 2, 3) FROM DUAL;
      
        
        
      2
      'B' matches the second pair, so it returns 2.

      Part 03 · Time Zones
      
    
      DATE and the TIMESTAMP family
      
    
      Simple meaning: DATE stops at whole seconds. TIMESTAMP adds fractions of a second. Two more versions add time zone awareness.
      
  
      
  
      
    
      DATECentury, year, month, day, hour, minute, second09-OCT-26Literal: DATE '2026-10-09'
      
    
      TIMESTAMP [(p)]DATE + fractional seconds. p = 0–9 digits, default 609-OCT-26 02.30.15.123457 PMLiteral: TIMESTAMP '2026-10-09 14:30:15.123457'
      
    
      TIMESTAMP [(p)] WITH TIME ZONETIMESTAMP + the time zone offset or region, stored with the value09-OCT-26 02.30.15.123457 PM +05:30Literal: TIMESTAMP '2026-10-09 14:30:15 +05:30'
      
    
      TIMESTAMP [(p)] WITH LOCAL TIME ZONEStored converted to the database time zone; shown in your session's time zone. No offset is stored or shown.09-OCT-26 02.30.15.123457 PMUsed as a column type
      
  
      
  
      
    
      
      
      2Fractional second precision · slide p
      
      
      
      
      Value inserted: 14:30:15.123456789
      
      
      
      
      
      
      When the column has fewer digits than the value, Oracle rounds the fraction to fit.
      
    
      
    
      
      
      
        
      3Column definitions
      
        
      CREATE TABLE race_results (
  runner     VARCHAR2(30),
  finished   TIMESTAMP(3),
  logged_at  TIMESTAMP WITH TIME ZONE,
  seen_at    TIMESTAMP WITH LOCAL TIME ZONE
);
      
      
      
      
      
        
      6Quick check
      
        
      What is the default fractional-second precision of TIMESTAMP?
      
        
        
      6
      Default is 6 digits (microseconds). The range is 0 to 9.
      
      
      
    
      
  
      

      



      
  
      
    
      Time Zones · TIMESTAMP WITH TIME ZONE
      
    
      One moment, many clocks
      
    
      Simple meaning: 10:00 in Mumbai and 04:30 in London are the same moment. TIMESTAMP WITH TIME ZONE stores the clock reading and the offset, so Oracle always knows the exact moment.
      
  
      
  
      
    
      2Set a moment · see it around the world
      
    
      
      
      
      
      
    
      
    
      
    
      
    
      00:0006:0012:0018:0024:00
      
  
      
  
      
    
      
      
      5Comparing values with different zones
      
      
      
      
      
      
      Oracle compares moments, not clock readings. Two values written in different zones are equal if they describe the same instant (same UTC time).
      
    
      
    
      
      
      
        
      3SQL syntax
      
        
      TIMESTAMP 'YYYY-MM-DD HH24:MI:SS[.ff] {+|-}hh:mi'
TIMESTAMP '2026-10-09 10:00:00 Asia/Kolkata'

-- show it in another zone
ts AT TIME ZONE '-05:00'
      
        
      An offset like +05:30 is fixed. A region name like 'America/New_York' also follows daylight saving time.
      
      
      
      
      
        
      6Quick check
      
        
      Is TIMESTAMP '2026-10-09 12:00:00 +00:00' equal to TIMESTAMP '2026-10-09 17:30:00 +05:30'?
      
        
        
      Yes
      17:30 at +05:30 is 12:00 UTC. Same moment.
      
      
      
    
      
  
      

      



      
  
      
    
      Time Zones · The big comparison
      
    
      Same row, three column types
      
    
      Simple meaning: insert one value into three columns, then change your session's time zone. TIMESTAMP never changes. WITH TIME ZONE keeps its own zone. WITH LOCAL TIME ZONE re-displays itself in your zone.
      
  
      
  
      
    
      2Step 1 · insert a row

      4When to use which
      
      
      
        
      TypeStores zone?Changes with session?Good for
      
        
      TIMESTAMPNoNoLocal events where zone doesn't matter
      
        
      WITH TIME ZONEYesNo (shows its own zone)Flights, meetings: "10:00 Mumbai time"

      6Quick check
      
        
      A row shows 10:00 in a WITH LOCAL TIME ZONE column for a user at +05:30. What does a user at +00:00 see?
      
        
        
      04:30
      Same moment, shown in the viewer's zone: 10:00 − 5:30.
      
      
      
    
      
  
      

      



      
  
      
    
      Time Zones · Functions
      
    
      Whose clock is it?
      
    
      Simple meaning: the server has an operating-system clock, the database has a time zone, and your session has a time zone. Each "now" function reads one of them. Change the zones and see which cards move.

      FunctionReturnsTime zone used
      
        
      SYSDATEDATEServer OS
      
        
      SYSTIMESTAMPTIMESTAMP WITH TIME ZONEServer OS
      
        
      CURRENT_DATEDATESession
      
        
      CURRENT_TIMESTAMPTIMESTAMP WITH TIME ZONESession
      
        
      LOCALTIMESTAMPTIMESTAMPSession
      
        
      SESSIONTIMEZONEThe session's zone (text)Session
      
        
      DBTIMEZONEThe database's zone (text)Database
      
      
      
    
      
    
      
      
      
        
      4Changing the session zone
      
        
      ALTER SESSION SET TIME_ZONE = '-05:00';
ALTER SESSION SET TIME_ZONE = 'Asia/Kolkata';
ALTER SESSION SET TIME_ZONE = LOCAL;
ALTER SESSION SET TIME_ZONE = DBTIMEZONE;
      
        
      Trap: DBTIMEZONE does not change SYSDATE. SYSDATE follows the server's operating system clock. DBTIMEZONE is used to store WITH LOCAL TIME ZONE values.
      
      
      
      
      
        
      6Quick check
      
        
      You run ALTER SESSION SET TIME_ZONE = '+09:00'. Which changes: SYSDATE or CURRENT_DATE?
      
        
        
      CURRENT_DATE
      It follows the session time zone. SYSDATE follows the server OS.
